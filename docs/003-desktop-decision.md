Durante el desarrollo de utilizando amabas herrammientas, pude comprender las ventajas y desventajas de utilizar _Tkinter_ versus _PyQt6_
tkinter es una buena herramienta para empezar y lograr compreder de donde vienen la parte desktop, su desarrollo permite mas libertades y ayuda a manejar los ventanas
y las acciones, por otro lado pyqt es para toda persona que quiere algo mas profesional y maneja el _POO_ ya que todo es un objeto y se puede manejar de esa manera
permite un manejo mas sencillo de los layout ya que te permite por medio de una configuración base poder controlar, tambien su creacion de widget te ayudar a compreder el uso del mismo
y darte cuanta que en proyectos grandes te facilita el timpo de desarrollo.

El _PyQt_ tiene una curva de aprendizaje mayor, si conoces alguna tecnologia manejada en widget es una ventaja que te puede facilitar, el hecho de que esta herramienta cuenta con menus complejos, tablas avanzadads, QThread mas robusto es la gran ventaja, en este caso no fue necesario entrar a fondo sobre ello, sin embargo, todos los que estamos en desarrollo de aplicaciones sabemos que las aplicaciones tienden a crecer y empezar con esta herramienta es la mejor ventaja que tienes sobre el futuro, al momento de ser hacer las united test si tu proyecto de Pyqt esta bien estructurado sera mas facil hacer las united test.

Para finalizar podria decir que si es necesario dedicarle un tiempo a la curva de aprendizaje de alguno de estos dos framework para paython desktop me iria sin lugar a dda por la segunda ya que en un ambito profesional
sera el mas usado, por los motivos antes mencionados.

## Matriz comparativa.

| Criterio               | Tkinter            | PyQt6                    |
| ---------------------- | ------------------ | ------------------------ |
| Curva de aprendizaje   | Más fácil          | Media                    |
| Apariencia visual      | Básica             | Profesional / Moderna    |
| Widgets disponibles    | Limitados          | Muy completos            |
| Tablas avanzadas       | Básicas (Treeview) | Potentes (Model/View)    |
| Arquitectura escalable | Limitada           | Muy escalable            |
| Unit testing UI        | Difícil            | Mejor soporte (QTest)    |
| Sistema de eventos     | Simple             | Señales y slots robustos |
| Animaciones            | Muy limitado       | Integradas               |
| Manejo de hilos        | Manual y delicado  | QThread estructurado     |
| Dependencias           | Incluido en Python | Librería externa         |
| Rendimiento            | Bueno              | Muy bueno (Qt C++)       |
| Uso profesional        | Bajo               | Alto (empresarial)       |
| Comunidad              | Grande             | Muy grande               |
| Tamaño ejecutable      | Más pequeño        | Más pesado               |
| Personalización visual | Limitada           | Muy alta (QSS tipo CSS)  |
